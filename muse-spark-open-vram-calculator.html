Reading the results like a pro

  • The 512GB Mac Studio story: NVFP4 total (~465GB) fits in 512GB unified memory with ~47GB headroom — the cheapest single-box way to run this model. Q4_K_M (~535GB) does not fit one box; you need 2×.
  • BF16 is datacenter-only: 1,787GB total means 16× H200 or equivalent. FP8 (905GB) fits a single 8× H200 / 8× MI300X node.
  • It's MoE: 42B active params mean tokens/s is far better than a dense 816B — but VRAM must still hold all 816B of weights.

FAQ

How much VRAM does Muse Spark Open need?

816B parameters → 1,632GB in BF16, 816GB in FP8, 408GB in the official NVFP4 variant. Add ~8% runtime overhead plus KV cache on top.

Can it run on a Mac Studio 512GB?

Yes — with the NVFP4 quantization (~465GB total incl. overhead). BF16/FP8 need multi-box or datacenter GPUs.

Is NVFP4 lossless?

No — 4-bit floating point trades some quality for 4× memory cut. Meta ships an official NVFP4 checkpoint, which signals production-grade quality at that precision for most tasks; run your own evals if precision matters.

Does GGUF Q4 work?

Community GGUF quants at ~0.58B/param land near 473GB weights — over one 512GB Mac once overhead is counted; plan for 2 boxes or NVFP4 instead.
